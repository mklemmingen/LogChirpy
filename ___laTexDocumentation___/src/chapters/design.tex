\section{Technology Selection and Architectural Rationale}

\textbf{Cross-Platform Development Framework: React Native with Expo}

\textbf{Why React Native with Expo:} Selected for cross-platform deployment while maintaining native performance needed for real-time ML.

\textbf{Technical Advantages:}
\begin{itemize}
    \item \textbf{Single Codebase:} One source code for both iOS and Android platforms, reducing development time compared to separate native apps
    \item \textbf{Rich Ecosystem:} Access to extensive third-party libraries and community solutions
    \item \textbf{Fast Development:} Hot reload enables rapid iteration and debugging
    \item \textbf{Native Module Support:} Easy integration with platform-specific native modules for performance-critical features
\end{itemize}

\textbf{Implementation Challenge:} Transition from ExpoGo to Custom Development Client was necessary to support ML model integration and advanced features

\textbf{ML Framework Integration}

\textbf{On-Device Processing:} The system uses local ML processing through TensorFlow.js and MLKit frameworks, enabling offline object detection, image classification, and audio-based bird identification without requiring internet.

\textbf{Strategic Advantages:}
\begin{itemize}
    \item \textbf{Privacy Protection:} Local data processing ensures user privacy and eliminates data transmission risks
    \item \textbf{Offline Operation:} Full offline functionality for use in remote field locations
    \item \textbf{Real-time Performance:} Low-latency processing for live bird identification
    \item \textbf{Cost Efficiency:} No recurring API costs due to self-contained ML infrastructure
\end{itemize}

\textbf{Model Optimization Strategy:} Implementation of custom bird classification model conversion to TensorFlow Lite (.tflite) format, achieving mobile-optimized performance while maintaining classification accuracy suitable for field research applications

\textbf{Hybrid Database Architecture Framework}

\textbf{Dual-Layer Data Management Strategy:} The system implements a sophisticated hybrid approach combining local SQLite databases with Firebase Cloud synchronization, optimizing both offline accessibility and cross-device data consistency.

\textbf{Architectural Components:}
\begin{itemize}
    \item \textbf{Local Storage Layer:} SQLite implementation providing offline-first data persistence and high-performance local access patterns
    \item \textbf{Cloud Synchronization Layer:} Firebase Firestore integration enabling seamless cross-device data synchronization and backup capabilities
    \item \textbf{Offline-First Design Principle:} Local database serving as primary data source with optional cloud backup, ensuring functionality independence from network connectivity
\end{itemize}

\textbf{System Benefits:}
\begin{itemize}
    \item \textbf{Complete Offline Functionality:} Full application capability regardless of network availability
    \item \textbf{Cross-Device Data Continuity:} Seamless synchronization across multiple user devices
    \item \textbf{User-Controlled Cloud Integration:} Granular user control over cloud data usage and privacy settings
    \item \textbf{Network Resilience:} Fault-tolerant operation during network disruptions or connectivity limitations
\end{itemize}

\section{Unified ML Pipeline}

\textbf{Original Dual-Pipeline Problems:}
\begin{itemize}
    \item \textbf{Race Condition Issues:} Separate image and audio processing loops caused systematic resource conflicts and unpredictable execution patterns
    \item \textbf{File Stability Problems:} Persistent "File stability timeout after 3000ms" errors disrupting ML processing workflows
    \item \textbf{Audio Recording Conflicts:} "Only one Recording object can be prepared at a given time" limitations preventing concurrent operations
    \item \textbf{Resource Exhaustion:} Multiple simultaneous ML operations overwhelming device computational resources
\end{itemize}

\textbf{Sequential Processing Solution:} The unified pipeline implements sequential ML operations within a controlled loop, eliminating concurrency issues:

\begin{lstlisting}[style=javascript, caption=Unified Pipeline Service Implementation, label=lst:unified_pipeline]
class UnifiedMLPipelineService {
  async runPipelineCycle() {
    try {
      // === IMAGE PROCESSING PHASE ===
      this.updateState('capturing_image');
      await this.processImagePhase();
      
      // Inter-phase delay for resource management
      await this.delay(100);
      
      // === AUDIO PROCESSING PHASE ===
      if (this.config.hasAudioPermission) {
        this.updateState('recording_audio');
        await this.processAudioPhase();
      }
      
      // === WAITING PHASE ===
      this.updateState('waiting');
      await this.delay(Config.camera.pipelineDelay * 1000);
      
    } catch (error) {
      this.handlePipelineError(error);
    }
  }
}
\end{lstlisting>

    \item \textbf{Resampling:} Uniform 48,000 Hz target frequency for consistent model input requirements
    \item \textbf{Format Conversion:} Int16 to Float32 transformation optimizing ML model processing
    \item \textbf{Duration Standardization:} Precise 144,000 sample normalization (3-second clips) for model compatibility
    \item \textbf{High-Pass Filtering:} 200 Hz cutoff frequency implementation for background noise elimination
\end{enumerate}

\textbf{Dual-Model Inference Architecture:}
\begin{lstlisting}[style=javascript, caption=Dual-Model Audio Classification Implementation, label=lst:dual_model]
const classifyAudio = async (audioSamples: Float32Array, location?: Location) => {
  // Primary audio classification model
  const audioLogits = await primaryModel.predict(audioSamples);
  const audioProbs = sigmoid(audioLogits);
  
  // Meta location model (when geographic data available)
  if (location) {
    const weekCosine = calculateWeekCosine(new Date());
    const metaInput = [location.latitude, location.longitude, weekCosine];
    const metaProbs = await metaModel.predict(metaInput);
    
    // Probability blending (30% meta-model influence)
    const metaInfluence = 0.3;
    const finalProbs = audioProbs.map((audioProb, i) => 
      audioProb * (1 - metaInfluence + metaInfluence * metaProbs[i])
    );
    
    return finalProbs;
  }
  
  return audioProbs;
};
\end{lstlisting>

class SpeciesMappingService {
  async mapToSpecies(scientificName: string, language: string = 'en') {
    // 1. Direct scientific name search
    let species = await this.searchByScientificName(scientificName);
    
    if (!species) {
      // 2. Subspecies fallback (remove subspecies designations)
      const baseSpecies = scientificName.split(' ').slice(0, 2).join(' ');
      species = await this.searchByScientificName(baseSpecies);
    }
    
    if (!species) {
      // 3. Fuzzy matching with Levenshtein distance algorithm
      species = await this.fuzzySearch(scientificName);
    }
    
    // Return localized species names
    return this.localizeSpecies(species, language);
  }
  
  async fuzzySearch(query: string): Promise<Species | null> {
    const threshold = 0.8;
    let bestMatch = null;
    let bestScore = 0;
    
    for (const species of this.speciesCache) {
      const score = this.calculateSimilarity(query, species.scientific_name);
      if (score > threshold && score > bestScore) {
        bestMatch = species;
        bestScore = score;
      }
    }
    
    return bestMatch;
  }
}

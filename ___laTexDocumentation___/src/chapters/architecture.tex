\chapter{System Architecture and Design}

\section{Architectural Overview and Design Principles}

LogChirpy uses a modular software architecture for cross-platform development. The system supports scalable bird data collection and processing with good performance on mobile devices.

\textbf{Technology Stack and Framework Selection:}
\begin{itemize}
    \item \textbf{Frontend Framework:} React Native with Expo SDK for cross-platform deployment
    \item \textbf{ML Architecture:}
    \begin{itemize}
        \item react-native-fast-tflite for audio classification with BirdNET models
        \item MLKit integration for object detection and image classification
        \item Local .tflite models for offline processing (no cloud dependencies)
    \end{itemize}
    \item \textbf{Database Systems:}
    \begin{itemize}
        \item SQLite for local bird observations and 33,000+ species encyclopedia
        \item Firebase Firestore for optional cloud synchronization
    \end{itemize}
    \item \textbf{Authentication:} Firebase Authentication with offline fallback mode
    \item \textbf{Mapping:} OpenStreetMap integration for bird sighting locations
\end{itemize}

\begin{itemize}
    \item \textbf{Modular Design Architecture:} Clear separation of concerns across feature domains (Authentication, Observations, ML Processing, Media Management)

\section{BirDex Encyclopedia Architecture}

\textbf{Comprehensive Species Database System:}

The BirDex encyclopedia represents one of LogChirpy's major architectural achievements, transforming a massive CSV dataset into a fully functional multilingual bird encyclopedia. The system manages over 33,000 global bird species with comprehensive metadata and localized content through \texttt{services/databaseBirDex.ts}.

\textbf{Data Processing Pipeline:}

\begin{lstlisting}[style=javascript, caption=BirDex Database Schema, label=lst:birdex_schema]
-- BirDex comprehensive species database (databaseBirDex.ts)
-- 33,000+ global bird species with multilingual support
CREATE TABLE birddex (
    species_code           TEXT    PRIMARY KEY,
    english_name           TEXT    NOT NULL,
    scientific_name        TEXT    NOT NULL,
    category               TEXT,
    family                 TEXT,
    order_                 TEXT,
    range                  TEXT,
    de_name                TEXT,    -- German names
    es_name                TEXT,    -- Spanish names
    fr_name                TEXT,    -- French names
    ukrainian_name         TEXT,    -- Ukrainian names
    ar_name                TEXT,    -- Arabic names
    hasBeenLogged          INTEGER DEFAULT 0
);

-- Performance optimization indexes
CREATE INDEX idx_birddex_english_name ON birddex(english_name);
CREATE INDEX idx_birddex_scientific_name ON birddex(scientific_name);
CREATE INDEX idx_birddex_family ON birddex(family);
\end{lstlisting}

\textbf{Encyclopedia Features:}
\begin{itemize}
    \item \textbf{Advanced Search:} Multi-language name lookup across all supported languages
    \item \textbf{Taxonomic Filtering:} Search by family, order, geographic range
    \item \textbf{Educational Quizzes:} Interactive species identification testing
    \item \textbf{Visual Integration:} Each species paired with locally stored Wikimedia images
    \item \textbf{Performance Optimization:} Strategic indexing and pagination for 33,000+ records
\end{itemize}

\textbf{Multi-Language Data Enrichment:}
The encyclopedia system processes raw taxonomic data through comprehensive translation workflows, adding German, Spanish, French, Ukrainian, and Arabic common names to each species entry. This creates a truly multilingual reference system accessible across diverse user communities.

\section{Logging System Architecture}

\textbf{Multi-Modal Observation Management:}

The logging system serves as LogChirpy's core functionality, integrating all other architectural components into a cohesive observation workflow. The system handles three distinct media types (images, audio, video) combined with ML predictions, manual entries, GPS coordinates, and taxonomic classifications.

\textbf{Logging Workflow Architecture:}

\begin{lstlisting}[style=javascript, caption=Bird Observation Data Structure, label=lst:observation_schema]

\textbf{Draft Management System:}
The \texttt{contexts/LogDraftContext.tsx} provides persistent draft storage using AsyncStorage, enabling auto-save functionality and recovery of incomplete observations. This ensures users never lose progress during field observations, even with app interruptions.

\textbf{Media Integration:}
The logging system integrates closely with device storage through \texttt{services/photoStorageService.ts} and the gallery interface. Captured media is immediately available for review, organization, and export through \texttt{app/(tabs)/gallery.tsx}, creating a seamless workflow from capture to archival.

\textbf{Audio Classification System:}
The \texttt{services/ultraSimpleBirdClassifier.ts} implements BirdNET dual-model architecture adapted from the whoBIRD project. The system uses \texttt{react-native-fast-tflite} for stable mobile integration, processing 3-second audio clips at 48kHz with location-based enhancement when GPS data is available.

\textbf{Image Detection Integration:}
Visual processing uses MLKit packages from Infinite Red for object detection and image classification. The system captures photos at reduced quality (0.3) for ML processing, detects objects, crops detection regions, and classifies each cropped section for bird identification.

\textbf{OpenAI-Powered Translation System}

The multilingual encyclopedia required translating 33,000+ bird species names across five target languages (German, Spanish, French, Ukrainian, Arabic). This massive undertaking utilized OpenAI's API as the primary translation engine with comprehensive fallback strategies.

\textbf{Translation Architecture (\texttt{dev/scripts/\_birdyDex\_massTranslationScripts/}):}

\begin{lstlisting}[style=javascript, caption=Translation System Implementation, label=lst:translation_system]
// Core translation workflow with OpenAI integration
const translateSpeciesBatch = async (speciesBatch) => {
  // 1. Public API fallback attempts
  for (const publicAPI of publicBirdAPIs) {
    try {
      const publicResults = await tryPublicAPI(speciesBatch, publicAPI);
      if (publicResults.coverage > 0.8) {
        return publicResults;
      }
    } catch (error) {
      console.warn(`Public API ${publicAPI.name} failed, trying next`);
    }
  }
  
  // 2. OpenAI fallback for comprehensive coverage
  const openAIResults = await translateWithOpenAI(speciesBatch, {
    model: 'gpt-4',
    maxTokens: 2000,
    temperature: 0.1, // Low temperature for consistent translations
    retryAttempts: 3,
    rateLimitBackoff: true
  });
  
  return openAIResults;
};
\end{lstlisting}

\textbf{Translation System Features:}
\begin{itemize}
    \item \textbf{Hybrid API Strategy:} Public bird APIs first, OpenAI as comprehensive fallback
    \item \textbf{Cost Optimization:} Minimize OpenAI usage through public API prioritization
    \item \textbf{Quality Assurance:} Low-temperature GPT-4 settings for consistent translations
    \item \textbf{Batch Processing:} Efficient API usage through intelligent batching
    \item \textbf{Resume Functionality:} Automatic recovery from interruptions with progress tracking
    \item \textbf{Caching System:} Persistent storage to avoid re-translating completed entries
    \item \textbf{Rate Limit Management:} Exponential backoff and quota monitoring
    \item \textbf{Multi-Model Fallback:} Automatic fallback between GPT-4 and GPT-3.5 based on availability
    \item \textbf{Progress Monitoring:} Real-time progress tracking with periodic CSV exports
\end{itemize}

\textbf{Data Processing Pipeline:}
\begin{enumerate}
    \item \textbf{CSV Input Processing:} Load Clements v2024 taxonomy with 33,000+ species
    \item \textbf{English Name Enrichment:} Query public APIs for English common names
    \item \textbf{Public API Translation:} Attempt translation through free ornithological APIs
    \item \textbf{OpenAI Enhancement:} Fill gaps and enhance quality through GPT-4 translations
    \item \textbf{Quality Validation:} Validate translations and handle special cases
    \item \textbf{Export Generation:} Produce final \texttt{birds\_fully\_translated.csv}
    \item \textbf{Database Integration:} Import enriched data into app's SQLite database
\end{enumerate}

\textbf{Translation Quality Management:}
The system implements comprehensive quality controls including validation of translation completeness, detection of untranslated scientific names, handling of extinct species and regional variants, and maintenance of taxonomic accuracy across all target languages.

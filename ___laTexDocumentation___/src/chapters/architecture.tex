\chapter{System Architecture and Design}

\section{Architectural Overview and Design Principles}

LogChirpy uses a modular software architecture for cross-platform development. The system supports scalable bird data collection and processing with good performance on mobile devices.

\textbf{Technology Stack and Framework Selection:}
\begin{itemize}
    \item \textbf{Frontend Framework:} React Native with Expo SDK for cross-platform deployment
    \item \textbf{ML Architecture:}
    \begin{itemize}
        \item react-native-fast-tflite for audio classification with BirdNET models
        \item MLKit integration for object detection and image classification
        \item Local .tflite models for offline processing (no cloud dependencies)
    \end{itemize}
    \item \textbf{Database Systems:}
    \begin{itemize}
        \item SQLite for local bird observations and 33,000+ species encyclopedia
        \item Firebase Firestore for optional cloud synchronization
    \end{itemize}
    \item \textbf{Authentication:} Firebase Authentication with offline fallback mode
    \item \textbf{Mapping:} OpenStreetMap integration for bird sighting locations
\end{itemize}

\begin{itemize}
    \item \textbf{Modular Design Architecture:} Clear separation of concerns across feature domains (Authentication, Observations, ML Processing, Media Management)

\section{BirDex Encyclopedia Architecture}

\textbf{Comprehensive Species Database System:}

The BirDex encyclopedia represents one of LogChirpy's major architectural achievements, transforming a massive CSV dataset into a fully functional multilingual bird encyclopedia. The system manages over 33,000 global bird species with comprehensive metadata and localized content through \texttt{services/databaseBirDex.ts}.

\textbf{Data Processing Pipeline:}

\begin{lstlisting}[style=javascript, caption=BirDex Database Schema, label=lst:birdex_schema]
-- BirDex comprehensive species database (databaseBirDex.ts)
-- 33,000+ global bird species with multilingual support
CREATE TABLE birddex (
    species_code           TEXT    PRIMARY KEY,
    english_name           TEXT    NOT NULL,
    scientific_name        TEXT    NOT NULL,
    category               TEXT,
    family                 TEXT,
    order_                 TEXT,
    range                  TEXT,
    de_name                TEXT,    -- German names
    es_name                TEXT,    -- Spanish names
    fr_name                TEXT,    -- French names
    ukrainian_name         TEXT,    -- Ukrainian names
    ar_name                TEXT,    -- Arabic names
    hasBeenLogged          INTEGER DEFAULT 0
);

-- Performance optimization indexes
CREATE INDEX idx_birddex_english_name ON birddex(english_name);
CREATE INDEX idx_birddex_scientific_name ON birddex(scientific_name);
CREATE INDEX idx_birddex_family ON birddex(family);
\end{lstlisting}

\textbf{Encyclopedia Features:}
\begin{itemize}
    \item \textbf{Advanced Search:} Multi-language name lookup across all supported languages
    \item \textbf{Taxonomic Filtering:} Search by family, order, geographic range
    \item \textbf{Educational Quizzes:} Interactive species identification testing
    \item \textbf{Visual Integration:} Each species paired with locally stored Wikimedia images
    \item \textbf{Performance Optimization:} Strategic indexing and pagination for 33,000+ records
\end{itemize}

\textbf{Multi-Language Data Enrichment:}
The encyclopedia system processes raw taxonomic data through comprehensive translation workflows, adding German, Spanish, French, Ukrainian, and Arabic common names to each species entry. This creates a truly multilingual reference system accessible across diverse user communities.

\section{Logging System Architecture}

\textbf{Multi-Modal Observation Management:}

The logging system serves as LogChirpy's core functionality, integrating all other architectural components into a cohesive observation workflow. The system handles three distinct media types (images, audio, video) combined with ML predictions, manual entries, GPS coordinates, and taxonomic classifications.

\textbf{Logging Workflow Architecture:}

\begin{lstlisting}[style=javascript, caption=Bird Observation Data Structure, label=lst:observation_schema]
-- Primary table for bird spotting records (database.ts)
CREATE TABLE bird_spottings (
    id               INTEGER PRIMARY KEY AUTOINCREMENT,
    image_uri        TEXT,
    video_uri        TEXT,
    audio_uri        TEXT,
    text_note        TEXT,
    gps_lat          REAL,
    gps_lng          REAL,
    date             TEXT,
    bird_type        TEXT,
    image_prediction TEXT,    -- ML classification results
    audio_prediction TEXT,    -- BirdNET audio results
    synced           INTEGER DEFAULT 0,
    latinBirDex      TEXT     -- Link to BirDex species
);

-- Performance indexes
CREATE INDEX idx_bird_spottings_date ON bird_spottings(date);
CREATE INDEX idx_bird_spottings_synced ON bird_spottings(synced);
\end{lstlisting}

\textbf{Draft Management System:}
The \texttt{contexts/LogDraftContext.tsx} provides persistent draft storage using AsyncStorage, enabling auto-save functionality and recovery of incomplete observations. This ensures users never lose progress during field observations, even with app interruptions.

\textbf{Media Integration:}
The logging system integrates closely with device storage through \texttt{services/photoStorageService.ts} and the gallery interface. Captured media is immediately available for review, organization, and export through \texttt{app/(tabs)/gallery.tsx}, creating a seamless workflow from capture to archival.

\textbf{Audio Classification System:}
The \texttt{services/ultraSimpleBirdClassifier.ts} implements BirdNET dual-model architecture adapted from the whoBIRD project. The system uses \texttt{react-native-fast-tflite} for stable mobile integration, processing 3-second audio clips at 48kHz with location-based enhancement when GPS data is available.

\textbf{Image Detection Integration:}
Visual processing uses MLKit packages from Infinite Red for object detection and image classification. The system captures photos at reduced quality (0.3) for ML processing, detects objects, crops detection regions, and classifies each cropped section for bird identification.

\section{Knowledge Extraction and Translation}

\textbf{Wikipedia Integration and Image Extraction:}

\textbf{Real Implementation Architecture:}

The system implements two complementary approaches for Wikipedia integration:

\begin{itemize}
    \item \textbf{Bird Image Service} (\texttt{services/birdImageService.ts}): Manages bird image retrieval and caching
    \item \textbf{Development Scripts}: Python scripts for bulk data processing (in development directory)
\end{itemize}

\textbf{Wikipedia Name Localization (TypeScript):}
The production service fetches multi-language bird names through Wikipedia's langlinks API with chunked requests and error handling.

\textbf{Image Extraction (Python Development Script):}
A comprehensive Python script handles bulk image downloading from Wikimedia Commons with features including:
\begin{itemize}
    \item Rate limiting and API quota management
    \item Image optimization and WebP conversion for mobile devices
    \item Quality filtering and metadata extraction
    \item Resume functionality for large batch operations
    \item Manifest generation with image metadata
\end{itemize}

\textbf{Mass Translation System for 30,000+ Species:}

\textbf{Real Translation Implementation:}

The project implements a comprehensive OpenAI-powered translation system through Node.js scripts in \texttt{dev/scripts/\_birdyDex\_massTranslationScripts/}:

\textbf{Implementation Features:}
This implementation demonstrates practical integration of translation APIs within the constraints of an educational project, rather than novel translation methodology.
\begin{itemize}
    \item \textbf{OpenAI API Integration:} Uses ChatGPT for high-quality bird name translations
    \item \textbf{Automatic Resume Functionality:} Safely resumes interrupted translation batches
    \item \textbf{Caching System:} Persistent cache to avoid re-translating completed entries
    \item \textbf{Rate Limiting with Exponential Backoff:} Handles API quotas and request timing
    \item \textbf{Model Fallback:} Automatic fallback between GPT models based on availability
    \item \textbf{Progress Tracking:} Real-time progress monitoring with periodic CSV exports
    \item \textbf{Multi-Language Support:} Generates German, Spanish, Ukrainian, and Arabic names
\end{itemize}

\textbf{Translation Workflow:}
\begin{enumerate}
    \item \textbf{Data Input:} Processes Clements v2024 taxonomy CSV with 30,000+ species
    \item \textbf{English Enrichment:} First enriches entries with English common names
    \item \textbf{Multi-Language Translation:} Batch translates to target languages using OpenAI
    \item \textbf{Quality Validation:} Validates translations and handles edge cases
    \item \textbf{Output Generation:} Produces \texttt{birds\_fully\_translated.csv} for app integration
\end{enumerate}

\textbf{Data Processing and Export Framework:}

\textbf{Large-Scale Dataset Processing:}

The system implements efficient batch processing for handling the 30,000+ bird species dataset. The actual implementation uses specialized Node.js scripts (\texttt{dev/scripts/\_birdyDex\_massTranslationScripts/enrich-birddex-with-translations.js}) that provide:

\begin{itemize}
    \item \textbf{Memory-Efficient Processing:} Chunk-based processing with configurable batch sizes
    \item \textbf{CSV Import/Export:} Papa Parse library for robust CSV processing
    \item \textbf{Data Validation:} Automated validation and cleaning of species names and translations
    \item \textbf{Progress Tracking:} Real-time processing progress monitoring with periodic saves
    \item \textbf{Resume Functionality:} Automatic resume capability for interrupted translation batches
    \item \textbf{Rate Limiting:} Exponential backoff and API quota management
\end{itemize}

\textbf{String Comparison and Fuzzy-Matching in BirDex:}

\textbf{Robust Species Recognition with BirDex Search Implementation:}

The project implements advanced species matching through the \texttt{services/databaseBirDex.ts} service, which provides comprehensive species lookup capabilities:

\begin{itemize}

    \item \textbf{Scientific Name Normalization:} Handles common variations and format differences

\textbf{Actual Implementation Features:}
The \texttt{databaseBirDex.ts} service bridges whoBIRD audio predictions with the BirDex database, providing enriched metadata and species search functionality.

\section{Performance Optimization}

\textbf{ML Pipeline Optimizations:}
\begin{itemize}
    \item \textbf{Sequential Processing:} Elimination of race conditions through controlled pipeline execution
    \item \textbf{Quality Reduction:} 0.3 quality factor for ML processing to optimize performance
    \item \textbf{Result Limitation:} Display optimization showing top 2 results per category
    \item \textbf{Configurable Delays:} Adaptive cycle timing for diverse device capabilities
\end{itemize}

\textbf{Memory Management Strategy:}
\begin{itemize}
    \item \textbf{Automatic Cleanup:} Systematic removal of temporary files and cached data
    \item \textbf{Lazy Loading:} On-demand ML model loading to minimize memory footprint
    \item \textbf{Pagination:} Database query optimization with 20-item page segmentation
    \item \textbf{Image Compression:} Automatic compression protocols for reduced file sizes
\end{itemize}
